# LifeOS Implementation Plan

Complete roadmap for transforming LifeOS from a dev project into a daily-use productivity app.

> [!IMPORTANT]
> **Phase 0 (Data Safety) is a HARD prerequisite** for all other phases. The user is experiencing data loss that prevents daily use. Nothing else matters until this is fixed.

## Phase 0: 🛡️ Data Safety

**Goal:** Eliminate data loss so the user can trust LifeOS with their daily data.

### Database & Persistence

#### [NEW] [schema-update.sql](file:///Users/saranochirsereglen/Documents/lifeos/supabase/schema-update.sql)
SQL migration adding new tables:
- `tasks` — columns: `id`, `user_id`, `canvas_id`, `shape_id` (UNIQUE), `title`, `description`, `completed`, `due_date`, `priority`, `color`, `parent_task_id` (FK self-ref for subtasks), `goal_shape_id` (FK to connected goal), `created_at`, `updated_at`

## Phase 1: 🎯 Daily Driver

**Goal:** Replace pen & paper with features that take < 30 seconds to use.

### Daily Task Planner Node

#### [NEW] [DailyPlannerNodeShape.tsx](file:///Users/saranochirsereglen/Documents/lifeos/src/components/Canvas/shapes/DailyPlannerNodeShape.tsx)
A new Tldraw custom shape — the centerpiece of daily use:
- **Layout:** 3 columns — Daily Tasks (35%) | Daily Wins (35%) | Quick View (30%)
- **Date-aware:** Uses `new Date()` for the machine's current date, displays as header
- **Left column (Daily Tasks):**
  - Reads from connected task nodes or an internal task list
  - Checkbox per task, checked = completed, unchecked = ❌ dark fill (highly visible)
  - Tasks that were unchecked yesterday auto-appear as rolled over
- **Middle column (4 Daily Wins):**
  - Physical Win 💪, Mental Win 🧠, Spiritual Win 🙏, Honest Accountability ✅
  - These are **shared data** with habit nodes — checking here updates the habit node's check-in for today
  - To share data: read habit nodes from the editor store by type, match by name, and update their `checkIns` array
- **Right column (Quick View):**
  - Mini progress bars for each of the 4 life areas
  - Today's Pomodoro session count
  - Upcoming due dates

Shape props: `w`, `h`, [date](file:///Users/saranochirsereglen/Documents/lifeos/src/hooks/useHabitSync.ts#115-127), `taskIds` (array), `dailyWinHabitNames` (array of 4 habit names to link)

### Pomodoro Timer

#### [NEW] [PomodoroTimer.tsx](file:///Users/saranochirsereglen/Documents/lifeos/src/components/Canvas/PomodoroTimer.tsx)
Floating timer component:
- **Mode 1 — Deep Work:** 40min work → 5min break → repeat
- **Mode 2 — Hormozi Sprint:** 15min blocks, no break
  - On timer end: popup modal with single text input "What did you accomplish?"
  - User types one sentence → submit → next 15min starts
  - Sentences saved to `pomodoroSessions` in Zustand store (persisted to localStorage)
- Visual: circular countdown timer, mode indicator, session count
- Positioned as floating element (bottom-right or top area)
- Sound notification on timer end (subtle)
- Keyboard shortcut: `Space` to start/pause (when timer is focused)

#### [NEW] [pomodoro-storage.ts](file:///Users/saranochirsereglen/Documents/lifeos/src/lib/pomodoro-storage.ts)
- `savePomodoroSession()` — saves completed session with timestamp, mode, duration, and sentence log
- `getTodaySessions()` — retrieves today's sessions for Quick View
- Initially localStorage-only (can add Supabase table later)

## Verification Plan

Since there are no existing tests in the codebase and no test framework is configured, verification will be done via browser-based manual testing.

### Phase 0 Verification

**Test 1: Task persistence**
1. Run `npm run dev` to start the dev server
2. Open LifeOS in the browser
3. Create a task node, set title to "Test Task 123"
4. Wait 3 seconds for sync
5. Open Supabase dashboard → `tasks` table → verify the row exists with correct `shape_id` and `title`
6. Hard refresh the browser → verify the task node still appears with correct data

**Test 2: Canvas recovery**
1. In Supabase, manually corrupt the `canvas.document` column (set to `{}`)
2. Refresh the browser
3. Verify the app does NOT show a blank canvas — should show a recovery message or attempt to rebuild from `goals`/`habits`/`tasks` tables

**Test 3: Data export**
1. Create several nodes (goal, habit, task)
2. Click "Export Data" button
3. Verify a JSON file downloads containing all node data

### Phase 1 Verification

**Test 4: Daily Planner Node**
1. Create a Daily Planner node from the toolbar
2. Verify it shows today's date
3. Verify the 3-column layout renders correctly (35/35/30 split)
4. Create some habit nodes named "Gym", "Journal", "Praying", "Accountability"
5. In the Daily Planner properties, link these 4 habits as daily wins
6. Check a daily win in the planner → verify the corresponding habit node's check-in for today is also marked

**Test 5: Quick Log Panel**
1. Click the Quick Log tab on the left edge
2. Verify the panel slides out showing today's habits and tasks
3. Check off a habit → verify the habit node on the canvas also updates
4. Close the panel → reopen → verify state is preserved

**Test 6: Pomodoro Timer**
1. Start a Deep Work timer → verify 40:00 countdown
2. Let it run for a few seconds → pause → resume → verify time is correct
3. Switch to Hormozi Sprint mode → start timer → wait for 15:00 completion
4. Verify popup appears asking for one sentence
5. Type a sentence → submit → verify next timer starts
6. Check session history shows the completed sprint with the sentence

**Test 7: Habit Dashboard Node**
1. Create 3+ habit nodes with some check-in data
2. Create a Habit Dashboard node
3. Verify all habits appear with correct streak counts and completion rates
4. Toggle a habit check-in → verify the dashboard updates

**Test 8: Content Calendar Node**
1. Create a Content Calendar node
2. Verify current month displays with correct days
3. Click + on a date → verify the content scheduling form appears
4. Add a "Talking Head" for IG → verify it shows as a colored tag in that date cell
5. Navigate to next/previous month → verify correct rendering
